## 1. 立刻要修的一个坑（推翻我们自己的两份结论）

**`motono0223/ptcg-tutorial-1-replays-to-shards` 点名的静默错位，我们全中。**

> "`steps[t]` 的 action 记在 **`steps[t+1]` 同座位**；同步配对仅 65% 满足 host 契约（索引在界、数量
> min~max、无重复），下一步配对 99.4%。错了不报错，指标正常而标签错。"

我们在自己的 317 局上复核，实测格式更精确：**同一决策的 obs 会连续两步各出现一次
（前一步 action 为空、后一步 action 已填），等待对手时 obs 被反复投递且 action 一直为空。**
正确配对是 `obs@(t-1) ↔ action@t`。

| 检验 | 旧的"同一步"配对 | 新的正确配对 |
|---|---|---|
| host 契约合法率 | 86.3%（我们）/ 73.2%（对手池） | **100.00%**（17,632 决策） |
| `IS_FIRST` 不变量（我们恒答先手） | 208 次 type=1 + **158 次索引越界** | **395/395 = 100%** |
| 卡表可取性 | 只能靠"可见牌"重建 20~27 张 | **317/317 局都能取出双方精确 60 张** |

**受影响并已作废的结论**（已在 `别记`/`实验记录` 中标注，见 EXP-0104~0106）：
`train_bc.py` 的 BC 数据集（EXP-0089~0098）与 `tools/audit_decisions.py` 的行为审计（EXP-0099/0100）。
修正后审计结果变化极大：`DEVIATE_FROM_RULE` 从 21.7% → **3.7%**，`LOW_DAMAGE_ATTACK` 从 226 → **16**。

**通用教训（写进 `别再试.md` 方法论）**：解析别人格式的数据前，先用**自己 agent 的确定性行为**
（我们会恒答先手）做一次不变量校验；合法率 100% 才是对齐正确的证据。

## 2. 值得抽取的清单（按价值排序）

### T1 ★★★ 同一个强策略 + **换卡组**（最高性价比，无需训练）

`kellydannimao` 的实测是整个公开界最有价值的一张表：**同一个策略网络开不同卡组**，
对同一个对手（基线卡组）的 Bo3 得分率是 **0.09 / 0.44 / 0.47 / 0.55 / 0.79 / 0.88**。
五项对手 gauntlet 后，按天梯份额加权，两个最好卡组几乎打平（≈0.535）⇒ 需要**石頭剪刀布 + 份额加权**才算得清。

同一作者的另两条：
- **卡组效应可以从 pilot 效应里分离**：ridge 惩罚的 logistic Bradley-Terry，
  `logit P(i beats j) = (team_i + deck_i) − (team_j + deck_j)`，用 7 天 1,665 场天梯回放拟合，
  deck 效应区间 ±41~57 Elo。**不分离的话，强队的卡组会继承强队的评分。**
- 天梯事实（2026-10-19）：先手胜率 **56.9% [55.3, 58.4]**；**98.7%** 的先后手决策选"先手"；
  每场思考时间中位数 **17 s**（p90 69 s）⇒ **几乎没人在搜索**。

**我们的处境**：现在用的是 Dipam 的基线卡组（天梯份额 7.7%，deck 效应 **−134 ± 54**，是最差的一档）。
这是目前**唯一还能靠本地实验拿到确定收益**的杠杆，而且现在我们有原料了（每份回放都能取双方卡表）。

### T3 ★★ 工程契约（零成本、防提交级灾难）

- **Kaggle 取 `main.py` 里最后一个 callable**（按名字首次绑定顺序），不是叫 `agent` 的那个；
  观测是 dict 且允许属性访问；只有函数带第二参数时才传配置。
- **`main.py` 在第一次调用时才被 exec**，import 时间从第 1 局的 600 s 里扣。
- **一副牌只问一次**（`select is None` 在 match 开始时）⇒ 任何按局状态必须在 `current.round` 变化时重置。
  `dariushafshar` 实测：仅这一项修好，同一卡组下得分率 **0.40 → 0.48**。
- **每局 600 s 预算在天梯上是每局重置的**（2,406/2,406 局都是满的），而 PyPI 的
  `kaggle-environments 1.33.0` 是整场一份 —— 本地用它会比线上更严。
- **异常/非法动作/超时 = 整场判负**，不只是输一局。
- 确定性打包：`gzip(mtime=0)` + USTAR + `uid=gid=mtime=0`，配 sha256 与 `getnames()` 断言
  （woominyo / flexonafft 都这么做）。
- **两个静默 bug 值得单独记**：① 攻击表 **lazy 构建**会在 runner 恢复 `sys.path` 之后失败 → 空表 →
  所有招式 dmg=0 且不报错（motono0223 "我们曾发布此 bug"）；② `search_begin` 有
  `search_begin(obs, ...)` 与 `search_begin(obs.search_begin_input, ...)` 两种签名，
  用错会被 `except` 吞掉，搜索永远返回 None、静默退化成规则（aristophanivan 两份 notebook 都是这个状态）。

### T4 ★★ 规则 agent 的"最可维护写法"（如果还要继续用规则）

- 打分排序 + `maxCount` 截断（事实标准）；斩杀检测给超大分（`prize_value ≥ 剩余奖赏 → 50000`）。
- **对手建模 → 硬编码最大伤害表**：识别 archetype 后给 `opp_max_damage`（Crustle 120 / Hop 220 /
  Lucario 270 / Starmie 210），再算"能不能被打死"。比让规则去猜稳得多。
- **两段式判定**："先判打不死，再选目标"（strong-start-v10：特殊防御能量 × Hammer 数量决定是否改写伤害；
  Alakazam 的 Powerful Hand 用 `(手牌+估算增量)×20`）。
- `safe_draws = deckCount - my_prize - 1` 门控所有抽牌，防 deck-out。
- 全链路返回 `(score, reason)`，可解释可审计。
- ⚠️ 反面：这些规则作者的实测都不高（唯一带区间的规则 vs 策略 = **0.000**）。
  **规则细节的天花板由策略决定，不是由规则细节决定。**

### T5 ★ 训练配方（只有以后自己训才用）

公开界少见的完整 PPO 配方（motono0223，均无 LB 分数，仅供参照）：
- **奖励**：`R[t] = 0.15·((我奖赏[t]−[t+1]) − (对手[t]−[t+1])) + 0.985·R[t+1]`，终局 ±1 只在末步；
  ret 夹 [−1,1]，label=(ret+1)/2 供 BCE。
- **优势**：`adv = ret − (2·sigmoid(value_old) − 1)`，clamp ±2.0 后标准化；
  **baseline 与 return 必须同尺度**，否则退化成无 baseline 的 REINFORCE。
- CLIP 0.2 / ENT 0.005 / VF 2.0 / epochs 2 / lr 1e-4 + warmup + cosine（每代重置）；
  **采样 temperature=1.0**（argmax 自博弈会崩 95%→28%）。
- **预算按行数而非局数**；`MAX_GAME_DECISIONS=400` 硬上限。
- BC：CE + 2.0×BCE、有效 batch 7680、14 epochs、**holdout 按 shard 文件切**（按行切会泄漏）、
  门槛看 **value AUROC** 而不是 accuracy。
- 联盟：h2h 晋级门槛（≥0.5+margin）、bootstrap 双门槛、exploiter 轮、动作用不一致率衡量多样性、
  **`_model_is_proven()`：模型没通过晋级就不许接管**（把"模型不如规则"这种常见失败工程化挡住）。
