### 已验证的 ε

```bash
./run.sh measure_epsilon.py data/pool_explore_v3.jsonl
#   动作 != greedy 的比例 = 0.1125
#   E[1-1/n] = 0.7628   =>  反算 EPS = 0.1475   （设定 0.15 ✓）
```

推导：explorer 只在 `maxCount==1 且 minCount<=1` 时随机化，且在全部 option 中均匀选，
所以 `P(action ≠ greedy) = ε · (1 − 1/n)`，即 `ε = 实测不一致率 / E[1 − 1/n]`。

## 生成命令

```bash
# ε = 0.15，25 套卡组，每对 4 局（卡组顺序 × 座位 四路平衡）
PTCG_EPSILON=0.15 ./run.sh gen_pool_data.py \
    --agent agents/explorer.py \
    --games-per-pair 4 \
    --seed 0 \
    --out data/pool_explore_v3.jsonl
```

四路平衡的含义（`g` 是每对卡组内的局号）：

| g | 卡组顺序 | reverse | 效果 |
|---|---|---|---|
| 0 | A vs B | False | A 是玩家0，A 选先后手 |
| 1 | A vs B | True  | A 是玩家0，B 选先后手 |
| 2 | B vs A | False | B 是玩家0，B 选先后手 |
| 3 | B vs A | True  | B 是玩家0，A 选先后手 |

之前只交替 `reverse`、不交换卡组顺序，会让同一套卡组永远坐玩家0。

## ⚠️ 这批数据能干什么、不能干什么

**不能**直接拿来训能超过 greedy 的 Q。原因是结构性的：

```
采集和执行用同一个确定性策略  ⇒  a = f(s)
每个局面只被访问一次、只执行一个动作
⇒ P(win | s, a) == P(win | s)，动作不携带额外信息
```

ε=0.15 只是让**每条轨迹**的动作更随机，不会让**同一个局面**被多个动作试遍。
历史证据：ε = 0 / 0.3 / 0.6 三档，选项特征重要性只有 0.38% / 0.48% / 0.59%。

**能**作为 rollout 打标签的**状态源**：它提供了 260,025 个真实局面，
其中 1,033 个多选取决策、60,769 个单选取可探索决策，
并且 600 种 matchup 覆盖了全部卡组组合。真正的反事实标签要靠
从这些局面出发的 rollout 重新生成（见 `framework/rollout.py`）。

## 观察记录

- 全池平均 **217 决策/局**，最长 437，最短 17；少数对局在 turn 3 就以空场判负结束
- `SETUP_BENCH_POKEMON` 这个 context **从不出现**——铺后备是在 MAIN 阶段用 `PLAY` 完成的，
  所以 `rulebase` 的 `bench_full` 只对少数 `TO_BENCH` 生效
- 座位存在残余偏置：120 局测下来玩家0 胜率 0.417（自己选先后手）/ 0.467（对手选先后手），
  合起来 0.442。这与 EXP-0001 记录的 random 自对弈 0.4475 一致。
  **评估时必须继续用座位 × reverse 四路交替**，否则测出来的是座位优势不是策略优势

## 回合结构（决定整个策略设计的地基）

### 哪些动作会立刻结束本回合

引擎实测（`search_step` 从同一局面分叉）：

| 动作 | turn | yourIndex | 结论 |
|---|---|---|---|
| `PLAY` / `ATTACH` / `EVOLVE` / `ABILITY` / `RETREAT` | 不变 | 不变（还是自己出手） | 回合继续 |
| `ATTACK` | **+1** | **翻转** | **结束回合** |
| `END` | **+1** | **翻转** | **结束回合** |

26 万条真实记录的全量统计（"下一条记录的 turn 是否 +1"）：

| 动作 | 出现次数 | 结束回合计 | 占比 |
|---|---:|---:|---:|
| `END` | 37,016 | 36,990 | **99.9%** |
| `ATTACK` | 10,957 | 5,502 | **50.2%** |
| `NUMBER` | 615 | 270 | 43.9% |
| `CARD` | 54,004 | 5,810 | 10.8% |
| `PLAY` / `ATTACH` / `RETREAT` / `EVOLVE` / `ABILITY` | — | **0** | **0.0%** |

### 两个必须知道的细节

**① `ATTACK` 不是原子动作。** 选 `ATTACK` 之后有 49.8% 的情况会在**同一回合内**
进入后续选择（`CARD` 4,522 次 / `YES` 472 次 / `ENERGY` 458 次——招式效果需要选牌或确认），
解决完才真正结束回合。所以"攻击结束回合"只在效果结算完之后成立。

> 对 rollout 没有影响：rollout 一路打到终局，后续选择会被策略自然处理掉。
> 但任何"动作 = 一步 = 一个后果"的假设都会在这里出错。

**② `END` 在几乎 100% 的 MAIN 决策里都是可选项。**
这意味着**"要不要现在结束回合"是一个每回合都要做的决定**（MAIN 决策 163,560 次，
其中 `ATTACK` 可选的占 31.1%，而 `END` 几乎总是可选）。

> 这正是基于 V 的搜索灾难性失败（0.39）的结构性原因：
> 最有后果的决定恰恰是 V 判断不了的那个（"现在结束 vs 继续铺场"），
> 而它每回合都出现。实测 V 驱动的搜索有 **46%** 的决策选了 `END`，
> 而规则策略只在优先级最末才结束回合。系统性错误 + 每回合都犯 = 必输。

### 规模

```
每局 42 个回合 / 217 次选择 / 约 5.2 次 MAIN 决策每回合
```

**"一步" ≠ "一回合"**：一次回合内玩家会连续做约 5 个决策。

### 对 rollout 方案的直接影响

| 指标 | 值 |
|---|---|
| MAIN 决策/局 | 136 |
| 其中 `ATTACK` 可选（高价值决策点） | 31.1% → **约 42 次/局** |
| 单次决策评估成本（3 候选 × 8 rollout × 4.5 ms） | ~110 ms |
| 单局额外成本 | **~4.5 s/局** |
| n=400 局 | ~30 min（引擎并行约 2× → ~15 min） |

> 注意：**不能用"END 是否可选"当过滤条件**——它几乎总是可选，过滤等于没过滤。
> 有效的过滤条件是"`ATTACK` 是否可选"（31.1%）。
