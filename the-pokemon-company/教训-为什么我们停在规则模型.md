# 教训：为什么我们停在规则模型，而没去做那个 1000 分的策略

> 2026-10-24 复盘。触发点：移植公开强策略后 LB 从 **364.0 → 978.2**（同一窗口读数）。
> 这份文档只写**能带走的东西**：五条原因 + 对手做对了什么 + 下次开局的检查表 + 本项目的改造顺序。

---

## 0. 先摆事实

| | 我们（两周） | 公开第 3 名（Dipam / Team Unown Gradiant） |
|---|---|---|
| agent 类别 | 手写规则 + depth-1 PIMC rollout | 自对弈 PPO 训出来的 token-transformer |
| 观测 | 95 维手工特征 | **10,944 维**：160 个实体 token × 61 特征 + 64 选项槽 + 全局/决策块 |
| 卡牌语义 | 卡 id one-hot（320 词表） | `card_id_emb(64) ‖ card_static ‖ 卡面文本嵌入(128)` |
| 策略头 | 每个选项一行手工标量 → GBDT/MLP 打分 | **指针式**：`h[ptr1], h[ptr2]` 直接读目标 token 的隐状态 |
| 规模 | 无（或 ~几十万参数的小模型） | 4,465,812 参数（trunk **d=256 / 4 层 / 8 头 / FFN 512**） |
| 训练信号 | 我们自己造的标签（rollout 胜率 / 规则动作 / 环境胜负） | **只有终局 ±1** + 特权 critic + 辅助预测头 |
| 训练量 | REINFORCE 3.2 万局 × 4 轮 | **数十亿环境步**，10,850 SPS，2048 并行局/卡，51 个冻结对手的 league |
| LB | 364.0 | 1132.4（10-07 读数）；我们移植后同一窗口 **978.2** |

## 1. 五条原因（按决定性排序）

### ① 我们从来没有"看外面"这一步（最根本）

`git grep` 到今天之前的所有提交：**没有任何一处提到公开权重、别人的仓库、预训练模型**。
从第一周起问题就被定义成"从零造一个 agent"，全部实验都在自己仓库里闭环。

而这 978 分的**必要前提**是"别人已经训练好了"。这是**信息缺口，不是技术缺口**——
今天实际付出的成本是：搜 notebook 10 分钟 + 核 MIT 许可 + 逐字节校验（manifest 27/27）+ 修本地测量陷阱。

### ② 分期决策是对的，但"什么时候该上 NN"这个触发器判错了

原始分工（用户）是对的：先把经典方法打满拿基线，瓶颈明确需要语义理解时才上 NN。
**错在我的瓶颈判断**：我判定瓶颈是"搜索深度不够"和"数据饥饿"，于是继续在规则+搜索里加码；
没有判定出真正的瓶颈是 **自对弈训练规模**——那是我们跨不过去的墙，而不是"再想想就能绕过"的问题。

### ③ 把"推理算力"的结论用在了"训练算力"的轴上

`tools/measure_cost.py` 测出**推理余量 2,476×**，文档写成"算力免费"，于是所有推论都是
"算力免费 ⇒ 可以搜索"。但同一台机器是 12 核 CPU / 7 GB / 无 GPU：
对方的训练栈是 **C 环境链进 CUDA 扩展**、2048 并行局、10,850 SPS、数十亿步。
**"算力免费"只对推理成立，对训练完全不成立。** 我们从未评估后者。

### ④ 所有学习实验都是"在规则骨架上加小增量"，失败得都对，但都没证伪"整体替换"

| 试过的 | 结果 |
|---|---|
| V（LightGBM 价值） | AUC 0.78 ✅ 但不能选动作 |
| P（LTR 模仿） | top-1 0.9994 —— 天花板就是 greedy 自己 |
| Q（反事实 GBDT） | 选项重要性 34.79% ✅，选动作 **0.465** ❌ |
| MCTS + V/P | 打不过 greedy ❌ |
| REINFORCE + 规则锚 | 纯网络比规则差 **12.5pp**；含锚则**偏离规则 0%** ❌ |
| BC（正确对齐后） | 一致率 **52.4% > 规则 36.9%** ✅，但真打 **0.397 < 规则** ❌ |

它们共享同一个前提：**只从我们自己产生的数据里学，且表征是我们那 95 维**。
⇒ 正确结论是"**这个规模、这个表征下学不出来**"，不是"学习型路线不成立"。

### ⑤ 评估尺子把"低风险小改动"偏好固化了

只有 2 次计分提交 + Elo 持续漂移 ⇒ 本地镜像成为唯一可信尺子 ⇒ 决策偏向"本地能测出正增量的小改动"
（如 RETREAT/ATTACK 修复本地 0.27→0.76）。这种偏好**系统性排斥"换一个类别"**：
它的验证要跨驾驶员，而我们当时恰好测出"我们的 agent 开不动复杂卡组"，
于是把结论写成了"本地无法评估强策略"（`别再试.md` F3 / G3 关闭）。

**这条是错的**：跨驾驶员比较可以做，**只要两边驾驶员相同**——我们就是这么测出 0.885 / Bo3 0.9333 的。

## 2. 对手做对了什么（结构性差距，不是训练量）

1. **表征装得下关系型决策**。`ptr1/ptr2 → h[ptr]` 天生表达"把能量贴给**哪只**"、"进化成**哪张**"。
   我们的手工特征连"我们自己那条确定性规则"都只装得下 64.8%（无锚规则模仿上限）。
2. **没有老师可抄 ⇒ 被迫学真策略**。我们加了规则锚之后"偏离规则 0%"，看起来稳定，实际天花板焊死在规则上；
   去掉锚立刻比规则差 12.5pp。**锚在表征不够时是稳定器，但它同时是天花板。**
3. **卡牌语义来自文本嵌入**（128 维 PCA），新卡补行即可；我们的 one-hot 既不能泛化到 164 张新卡，
   也表达不了"检索/抽牌/加速"。手工角色标签（`plan_features.py`）追不上文本嵌入。
4. **特权 critic 是免费的方差削减**：训练时用 oracle（真实隐藏信息）当 baseline，发布时只用盲评头。
   我们自己有引擎，能拿到全部真实状态 —— 这个技巧对我们**零成本**，却从未用过。
5. **多样性与非传递性**：616 副卡组按概率抽样 + 51 个冻结对手的 league。我们只有 25 套自造卡组、无 league。

## 3. 下次开局的检查表（**第 0 步，1 小时**）

> **第 0 步（新增，必须最先做）**：按票数与时间把赛题公开 notebook / 仓库扫一遍，回答三个问题：
> 1. 有没有**可直接用的训练好的权重/完整代码**？
> 2. 它们的**许可证**是什么（能不能进提交包）？
> 3. 榜前的那些方案，**本质差别**是"策略/搜索/规则/卡组"里的哪一个？
>
> 这一步不影响"先把经典方法打满"的计划，它只是让你**第一天就知道外部高起点在哪、自己路径的天花板在哪**。

配套的三条：

* **区分推理算力与训练算力**。`measure_cost.py` 那种测量只说明"推理有余量"，不要据此推断"可以自对弈"。
* **任何"学习型"尝试，先问表征够不够**：用"学一个已知的确定性函数（我们自己的规则）"当标尺——
  如果学到 65%，说明特征装不下，先改表征，别加数据、别加容量（我们已经用五个测量验证过这条）。
* **测试协议要能跨驾驶员**：固定一个强驾驶员、换卡组/换对手，才是本地能做的"绝对强度"比较。

## 4. 本项目若要自己训，最小改造顺序

1. **观测 token 化**（160 token × 61 特征 + 64 选项槽），卡牌向量接**文本嵌入**；
2. **指针式选项头**（读 `h[ptr]`），多选按"一次一个 pick + STOP"分解；
3. **去掉规则锚**，改用**特权信息 critic**（本地引擎能拿到真实隐藏状态，oracle 免费）；
4. **league + 卡组池**（我们已有 172 副真实场卡组的语料）；
5. 最后才谈训练规模（CPU 只能做监督蒸馏；自对弈需要 ≥1 张 24 GB 卡，用 PufferLib(MIT) 那套训练器）。

第 1,2 步可以用**监督蒸馏**先验真：官方每日 dump（CC0，约 46 万决策/天）做 BC，
判据是"holdout 与强玩家一致率"能否从我们现在的 **52.4%** 提到 **70%+**。
提上去 ⇒ 表征对了，值得投训练；提不上去 ⇒ 瓶颈在标签/数据，"移植 + 卡组"才是对的投入方向。
