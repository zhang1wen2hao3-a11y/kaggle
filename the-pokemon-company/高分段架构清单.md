## A. Dipam token-transformer —— 目前唯一被多方复现的"高分底座"

**结构**（详见 `教训-为什么我们停在规则模型.md` 与 `docs/model.md`）：

- 输入：每步 **10,944 维** —— 160 个实体 token（`tok_int 5 + tok_float 56`）+ 64 个选项槽（`opt_int 6 + opt_float 8 + mask`）+ 全局/决策块 + 训练期 oracle 块。
- CardVec = `card_id_emb(64) ‖ 静态属性 ‖ 卡面文本嵌入(128 维 PCA)` + 招式/技能向量的 mean/max 池化。
- Trunk：pre-LN transformer，**d=256 / 4 层 / 8 头 / FFN 512**，CLS 用可学习 `readout`，全局与决策向量 `bcast(g‖d)` **逐 token 相加**；**无位置编码**（token 是集合）。
- 策略头：**指针式** —— 每个选项读 `h[ptr1]`、`h[ptr2]`（指到手牌卡 / 出战宝可梦 / 招式）。
- 双 critic：盲评头（发布）+ **oracle 特权头**（训练时看真实隐藏信息当 baseline）；另有 `aux_hand` / `aux_prize` 辅助头。

**凭什么高**：

1. **天量自对弈**。C 环境链进 CUDA 扩展，`--total-agents 2048`、**10,850 SPS**、数十亿环境步；51 个冻结对手的 league + 616 副卡组抽样。
2. **表征装得下关系型决策**（`h[ptr]` 指哪打哪）+ 卡牌语义来自**文本嵌入**，所以 164 张新卡补行即可用。
3. **特权 critic 降方差**（训练看隐藏信息、发布不看），这是零成本收益。
4. **可移植**：同一份权重跨届复用（补 Bo3 + 新卡行），这是它能被 5+ 个团队同时复现到 970~1132 的原因。

### A-补充：A 的"下一步优化方向"他们写了什么？

**结论：没有写 roadmap / future work。** 仓库是一次"成品发布"，只包含能复现最终提交的一切
（`README.md` / `docs/{training,model,eval,deck-pool,decklab,engine}.md`），没有"接下来做什么"章节。

但它**内建了三套持续改进机制**，等价于他们说的下一步：

| 机制 | 文档 | 作用 |
|---|---|---|
| **decklab**（卡组实验闭环） | `docs/decklab.md` | agent 提出卡组变体 → 评审 → 对**固定 checkpoint** 做 A/B → 通过才 append 进训练池；`pt_reload_decks` 支持**训练中热插新卡组**（`deck-pool.md §5`）。这就是"下一步优化方向"：**让卡组池持续长大** |
| **league 训练** | `training.md §10` | 51 个冻结历史 ckpt 当对手，防循环、防遗忘 |
| **eval battery + eval watch** | `eval.md`、`training.md §12` | 6 个 anchor 卡组 + 5 个候选卡组，训练中持续打分，决定续跑/分支 |

以及四个**明确记录的已知问题**（这才是真正的"待办"）：

1. **12 GB 卡上有未解决的静默停住**（`training.md §5`）：RTX 3060 在 `--total-agents 512 --minibatch 256`
   时第 4~5 个 rollout 卡在 `t=0/64`，**两个种子都能复现、GPU 100%、无任何报错**。24 GB 卡上百亿步正常。
2. **critic 先崩**（`training.md §9`）：value loss 会比 approx-KL 早约 10 个 epoch 失控，所以
   `--kl-skip` 之外必须单独设 `--vf-skip 0.5`；这是 band-aid，不是根治。
3. **Muon 的 1-D 参数路径必须打补丁**（同 §9）：上游对 LayerNorm gain / bias / readout 这类 1-D 参数
   用的是原始 sum momentum（步长由梯度幅值决定、不受学习率约束、无 weight decay），会和 logit readout
   形成"锐化反馈"而爆掉。他们的补丁是 1-D 参数改 EMA momentum + 独立解耦 wd（`--muon-wd-1d 0.01`），
   **且没有开关能退回原行为**。
4. **自对弈发现了一个规则级退化策略**（`training.md §14` "Solar Transfer 激活上限"）：某张卡的技能
   （"你的回合内想用多少次都行"、可逆、无对手响应窗口）构成**合法且无界的循环**，agent 可以在一个回合内
   无限重复 → 单局死在引擎步数上限。**关键洞见**：截断时**不重置终局标志**，于是 trainer 跨截断自举，
   "卡死"被读成**中性**而不是坏；而且**在折扣下"以后输"优于"现在输"，所以对处于劣势的 agent 来说拖延是正确玩法**，
   任何大到能扭转它的惩罚都超出 value-loss guard 能容忍的奖励尺度。
   他们的解法是**环境层面结构性封堵**：`PT_AB652_CARD / PT_AB652_CAP` 每座位每回合限 10 次，
   超出的激活从策略 mask 与随机对手的抽牌池里剔除（强制选项永不被过滤，回合结束永远可用）。

> ⚠️ 第 4 条对我们有直接价值：**如果我们以后自训，"拖延是劣势方的正确玩法"这个洞必须提前处理**，
> 否则训练信号会把"卡死"当成可接受结果。

### A-补充 1b：「预测对手手牌」在这套框架里到底怎么体现（2026-10-24 查证）

答案分三层，**部署时只有"事实"，预测只发生在训练期**：

| 层 | 内容 | 具体字段/代码 | 部署时用吗 |
|---|---|---|---|
| ① 公开事实 | 对手手牌**张数** | `GlobF.OPP_HAND`（`handCount/20`） | ✅ |
| ① 公开事实 | 手牌里**未知身份**的张数 | `GlobF.OPP_HAND_UNKNOWN = max(0, handCount − n_known_hand)/20` | ✅ |
| ① 公开事实 | **已被揭示**的手牌身份（按 serial 精确） | token 区 `Zone.OPP_HAND_KNOWN`（`encoder.py:276` 用 `tracker.opp_known_hand` 计数折叠） | ✅ |
| ② 训练期 oracle | 对手手牌真实构成（24 × `[id, count/4]`）、对手 deck/prize 拆分（24 × `[id, deck/4, prize/4]`）、我方奖赏（8 × `[id, count/4]`） | `buffers.py` 的 `oracle` 块（`ORACLE_F=136`） | ❌ 前向之前清零 |
| ③ 辅助预测头 | **从盲表征预测对手手牌构成**（按卡 id 的张数）＋ 每张未见牌是否在奖赏里 | `aux_hand = Linear(d+128, N_CARDS)`、`aux_prize = Linear(d, 1)`；标签取自 oracle 块 | ❌ 只做辅助 loss，**不回流到策略** |
| ④ 信念采样/搜索 | 对未知牌做分布假设、采样多世界做 rollout | — | ❌ 没有：他们的提交是**纯策略**（搜索实测 0.491 更差） |

`ptcg/tracker.py` 开头写得很明确：只维护"**不靠作弊就能推出来**"的东西——`my_unseen`（我方 deck∪prize）、
`opp_visible`、`opp_known_hand`（**只有被日志揭示的**；正常抽牌是 `DRAW_REVERSE`，身份保持未知）、`opp_known_deck`。
所以它对未知手牌**不做任何猜测**，只提供"已知/未知"的边界。

**对我们的意义**：`README.md` 里那条"对手推断模型 ❌ 未开始（缺 oracle 数据）"的阻碍**已经不存在了** ——
oracle 就是"我们本地引擎能直接读到的真实隐藏状态"，我们现在就能为每个决策记录它（此前只用它做 determinization 采样）。
最小改造：① 加"已知手牌身份"的多热 + 未知张数特征；② 加一个 aux 头预测对手手牌构成，用本地记录的真值当标签（不进策略）。

## B. Team Scio MLP —— 另一条完全不同的、**CPU 可行**的高分路线

**结构**（`agents/sa/policynet.py` / `features.py` / `optfeat.py`）：

- 稠密状态向量（盘面、HP、能量数、替补占用、奖赏差）+ **实体嵌入 d=16**（卡 id / 招式 id / 目标槽映射）+ **词袋式 mean-pool 嵌入**（我方手牌、我方弃牌、对手弃牌）。
- 打分：联合 MLP `[state_repr, option_repr]` → 对**合法选项列表做 listwise softmax**。
- 规模 ~70 万参数，**纯 NumPy，~1 ms/决策**（600 秒预算用不到 0.1 秒）。
- 外围：`tracker.py`（对手手牌/弃牌资源追踪）、`targeting.py`/`textdmg.py`（**算术守栏**）、`valuenet.py`/`vlook.py`（价值前瞻）。

**训练方式**：`scripts/train_policy.py --loss listwise --stream` —— **行为克隆**，数据来自回放。

**凭什么高**（作者自己给的对照表，这是最值钱的部分）：

| 干预 | 结果 | 含义 |
|---|---|---|
| MCTS 搜索 vs 快策略 | ❌ **0.323** | 低算力预算下搜索的信用分配方差太大 |
| 数据量 ×160（未筛选） | ❌ 胜率掉到 **0.440** | 训练准确率上去、实战下降——**模仿了弱玩家** |
| **按 Elo ≥ 1120 筛顶层对局** | ✅ **+115 Elo** | 选择性克隆把先验锚在高手决策空间 |
| **算术守栏**（致命 KO / 替补狙杀 / 防自锁） | ✅ **+0.104 胜率** | 确定性数学规则补上 softmax 尾部盲点 |
| Supporter 出牌顺序规则 | ✅ 统计显著 | 防止自己给自己卡回合 |

⇒ **不用 transformer、不用自对弈、一台 CPU 就能到 ~991**。代价是它没有 license。

## C. 规则 + 确定性搜索 —— 天花板比我们以为的高，但绑卡组

| 实现 | 做法 | 读数 |
|---|---|---|
| `aristophanivan`（improved-probabilistic / probability-v2） | 规则打分 + determinize 前瞻（beam/UCB 重排；注：其 beam 因 `TypeError` 被吞实际退化为纯规则） | **959.4**（被 matterhorn 的注释引用，"同一卡组"） |
| `woominyo` Alakazam+Dusknoir | 2423 行纯规则 + 公共日志反推回合归属 | **723.1** |
| `cggonzalezsc`(r21) / `woonomiyo`(v014) / `kozykappa`(belief_search) / `matterhorn`(sport_search) / `pixiux` / `flexonafft` | 规则 + 单步 determinize（`search_begin/step`），各自深度调参 | 在 `dariushafshar` 的 45 对 round robin 里 Bradley-Terry **78 ~ −368** |

**凭什么能上 900+**：**针对固定卡组**把伤害算术、奖赏节奏、检索顺序全部硬编码到极致（`aristophanivan` 那条注释特意写明"同一卡组"）。
**为什么不能更高 / 不可迁移**：换一副卡组就崩——这正是我们自己的经验（规则 + rollout 在我方卡组上能把胜率 0.27→0.76，但"我们的 agent 开官方复杂卡组"只有 0.16~0.20）。

## E. 交叉结论（可以拿去指导下一步）

1. **所有高分路线都建立在"别人的决策数据"之上**：要么自对弈产生（A），要么克隆高手回放（B），要么把某个卡组的正确下法硬编码（C）。**纯手写通用启发式**的上限大致在 300~400（就是我们）。
2. **在每个路线上，"搜索叠在策略上"都是负的**：Scio 0.323、kellydannimao 0.48~0.57、busyaprime 0.491、我们 31 项关闭方向。⇒ 不要再在评估器上投入。
3. **守栏（确定性覆盖）是正收益且廉价**：Scio **+0.104 胜率**；我们的历史最大单步收益也是这类修复（RETREAT vs ATTACK 本地 0.27→0.76）。但请注意：**守栏只能补盲点，不能替代策略**。
4. **数据质量 > 数量**：Scio 的 160 倍未筛选数据让胜率掉到 0.440，而按 Elo≥1120 筛顶层 **+115 Elo**。这条对我们后面做监督蒸馏是**直接可用的判据**。
5. **架构不是瓶颈**：4.47M 的 transformer 和 0.7M 的 MLP 都能到 ~1000。真正的差别在**训练信号来源**与**表征是否装得下关系型决策**。
