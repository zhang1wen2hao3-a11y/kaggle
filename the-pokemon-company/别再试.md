## 0. 判读约定

| 符号 | 含义 |
|---|---|
| `n` | 对局数 |
| `SE` | 标准误 = `0.5/√n`；n=300 → **2.9pp**，n=600 → 2.0pp，n=2000 → 1.1pp |
| `z` | `(胜率 − 0.5)/SE`；**|z| < 2 一律当噪声**，≥2.5 才算改进 |
| 对局层 | 让改动后的 agent 真打，测胜率 |
| 决策层 | 在单个决策上把候选都 rollout 打分，比"选中的动作"值多少 —— **灵敏一个数量级** |

**基线 agent**：`agents/ro_attack_w10.py`（= 线上配置：`MODE=attack, WORLDS=10, MARGIN=1.5, CANDS=all`）
**基线卡组**：`decks/sample_official.csv`

而 n=300 的 SE 是 2.9pp —— **做之前就该知道测不出来**。

**依赖什么**：B 类全部建立在「每局决策数少、单决策影响被稀释」这个前提上。若某个改动同时改变了几十个决策（如整表优先级），则不适用。

## D. 学习型模型（全部关闭）

| # | 试了什么 | 结果 | 为什么失败 |
|---|---|---|---|
| D1 | **V**（价值模型）1-ply 选动作 | **0.20** | V 只有 `s` 没有动作维度；V 的误差（~0.05）远大于动作间真实差异（~0.02） |
| D2 | 启发式 V | 0.25 | 同上 |
| D3 | **MCTS + V** | 0.39 | 同上；且系统性偏好 END（当时 `st_turn` 伪特征加剧） |
| D4 | MCTS + **P 先验裁剪** top_k=3 | 0.3725（400 局，低 5.2σ） | V 在"接近最优的动作之间"做选择时**有害** |
| D5 | 对照：`top_k=1`（等价 greedy） | **0.53** ✅ | 证明**管线正确**，问题不在接线 |
| D6 | **P（LTR 模仿）** | top1 = **0.9994** | 完美复刻 greedy ⇒ 结构上不可能超过自己的老师 |
| D7 | **Q(s,a) 反事实 GBDT** | **0.4650**（n=600, z=−1.72） | 见下面的"三个死因" |
| D8 | Q 换 margin 0.05/0.10/0.20 | 0.4450 / 0.4150 / 0.4250 | 学生加保险阀也救不回来 |
| D9 | AlphaZero 式自弈 | — | 改进算子断了（同 D7） |

### Q 失败的三个死因（都是结构性的，不是"训练不充分"）

1. **标签噪声 ≈ 信号**。标签 = 8~10 个二值世界的胜率，SE ≈ 0.18；而候选间真实差异均值只有 **0.1754**。
   回归 MAE **0.2604** > 信号本身。估算：「最好的动作」这个标签本身约 **1/3 是错的**。
2. **蒸馏把老师的"保险阀"丢掉了**。老师（rollout agent）= 规则策略 + 显著性检验（`z ≥ 1.5` 才偏离）。
   它的估值很噪，但**决定有保护**。我们蒸馏了估值、然后直接 `argmax` —— 于是学生的分歧
   恰好集中在"老师会弃权"的那个置信度区间。这是"一致率 63.6% 却打不过规则"的结构性原因。
3. **没有收益点（最硬）**。蒸馏只在两种情况下有价值：学生更便宜，或能用在老师去不了的地方。
   - 算力余量 **2,476×**（`tools/measure_cost.py` 实测）⇒ 不需要更便宜的学生
   - 老师去不了的地方（子决策）杠杆 **0.03pp** ⇒ 没有第二个收益点
   - "更准"结构上不可能（天花板 = 老师）

**依赖什么**：D1~D9 全部建立在「算力免费 + depth-1 评估器」上。若算力受限或引入深度搜索，D 类需要重估。
**注意**：「LLM 当标注器」也不属于这里 —— 它同样没有验证过的能力差，见 `下一步.md` §3。

## E. 方法论陷阱（不是"别再试"，是"别再犯"）

| # | 坑 | 今天付的代价 |
|---|---|---|
| **E1** | **赢家诅咒**：在一组候选里取最大值，最大值天然偏高（k=4 时约 +1.6σ，k=24 时约 +1.9σ） | 三个"赢家"全部在复测时蒸发：<br>`grass_heracross` 0.5875(n=160) → **0.5050**(n=600)<br>`lightning_zeraora` 0.5563 → **0.4867**<br>`playout_evolve` 0.5533 → **0.5035**(n=2000)<br>⇒ **扫描只能用来淘汰，不能用来选拔；第一名必须独立大样本复测** |
| **E2** | **LB 跨时刻相减** | `LB记录.md` 被修正**三次**。同一份提交 2 小时内 562.9 → 460.5 → 376.5；同一份代码两次提交读到 600.0 和 346.4。⇒ 只能在**同快照 + 同状态（都活跃/都冻结）**下相减，且提交后至少等 6 小时再读 |
| **E3** | **混淆变量** | `develop_first` 的 0.4167 混了"先出牌"和"**RETREAT 排在 ATTACK 之前**"两个因素；`official_dragapult_e20` 加能量时顺手砍了 `Rare Candy`。⇒ 一次只改一个变量，改完先问"我还动了什么" |
| **E4** | **静默退化（BUG-002）** | 本地 `play_match` 不送 `select=None`，导致 `main_rollout` 的时间预算计时器**跨局累加**，20 秒后该进程里后续所有对局**退化成纯规则**。征兆：0.08 s/局、算量差 4 倍的配置耗时**完全相同**。⇒ 任何带时间预算的 agent，评估框架必须显式 `reset()` |
| **E5** | **兜底掩盖 bug（BUG-001）** | 填充器把 `GameMemory` 的日志事件计数当"剩余张数"用，导致 99.5% 的局面池子不足、**凭空补了约 37 张基础能量**，而程序不崩不报错。⇒ 凡是"补默认值"的兜底都要**计数并暴露** |
| **E6** | **低估/高估杠杆** | 我今天三个直觉预判全错，且每次都高估 1~2 个数量级：子决策选牌估"有杠杆"→ 实际 0.03pp；"官方卡组会赢"→ 0.4533；"能量不足是主因"→ 加能量更差。⇒ **先算稀释效应（占比 × 单点提升），再决定要不要做** |
| **E7** | **只交替座位不交替 reverse** | 会让**我方在每一局都能选先后手**，胜率被抬高几十个百分点（我的 `dump_deck_turns` 第一版就踩了，跑出 7/12 的假象）。⇒ 必须四路交替（座位 × reverse） |
